# Smoke test runbook

Use this runbook for release-candidate and lab validation.

## Preconditions

- Omni `1.6.0` is reachable over HTTPS.
- The provider is running and healthy.
- OpenNebula has a Talos-capable VM template and network path.
- The Talos image is either already present or import-on-miss is configured.
- The target host bridge and gateway are in place before provisioning begins.

## Core smoke flow

1. Confirm provider registration in Omni.
2. Provision one control-plane node.
3. Confirm a VM is created in OpenNebula.
4. Confirm the Talos node appears in Omni.
5. Confirm the Talos hostname matches the VM name.
6. Add one worker node.
7. Remove one worker node and confirm the correct VM is deleted.
8. Delete the full cluster and confirm provider-owned VMs are gone.

## Additional live slices

Run these as separate short-lived validation clusters where practical:

- provider restart during provisioning
- import-on-miss for a missing Talos image
- reuse-existing-image without a second import
- observability checks during provision and delete

## Validated results on the single-host lab

Passed:

- provider registration
- control-plane bootstrap
- scale-out
- scale-down
- full cluster delete
- restart during provisioning without duplicate VM creation
- import-on-miss
- reuse-existing-image
- `/healthz`, `/readyz`, `/metrics`
- auth/session redaction in live logs

## Manual-networking compatibility note

`networkContextMode: manual` is not fully validated on the current single-host emulated qemu lab.

What was confirmed:

- the provider renders `NETWORK="NO"` with explicit `ETH*_` context keys
- the rendered context matches the Talos OpenNebula documentation for manual context on `ETHER` pools
- the VM boots successfully in OpenNebula

What did not validate:

- the guest never became reachable on the configured static IP
- the machine never created an Omni link on that lab

Treat manual networking as a compatibility item that must be revalidated on your own OpenNebula and hypervisor combination before relying on it in production.

## Useful repo-local helpers

The `.assh/` directory includes scripts for listing OpenNebula resources, rendering a provider config, and running a smoke workflow shell wrapper.

## Evidence to capture

- OpenNebula VM ID and name
- Omni machine request ID
- provider logs for instantiate and deprovision
- confirmation that auth values stay redacted in logs
- scale-down confirmation
- image import or reuse outcome
- `/healthz`, `/readyz`, and `/metrics` output during the run
