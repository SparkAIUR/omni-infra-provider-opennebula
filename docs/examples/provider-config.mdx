# Provider config example

This is a full runtime config example for the provider:

```yaml
providerID: opennebula
opennebula:
  endpoint: "https://opennebula.example.com/RPC2"
  templateName: "talos-omni-base"
  allowedTemplates:
    - "talos-omni-base"
  allowedDatastores:
    - "ssd-primary"
    - "ceph-images"
  allowedNetworks:
    - "talos-prod"
    - "talos-mgmt"
  imageNamePattern: "talos-opennebula-{{ .Arch }}-{{ .TalosVersion }}-schematic-{{ .SchematicID }}"
defaults:
  flavor: "small"
  firmware: "uefi"
  secureBoot: true
  graphicsEnabled: false
  networkContextMode: "auto"
  hostnameStrategy: "vm-name"
features:
  allowExplicitResources: true
  enableGPU: false
  hardDelete: false
imageManagement:
  importOnMiss: true
  requireChecksum: true
  artifactURLTemplate: "https://artifacts.example.com/talos/{{ .TalosVersion }}/{{ .Arch }}/disk.qcow2"
  checksumURLTemplate: "https://artifacts.example.com/talos/{{ .TalosVersion }}/{{ .Arch }}/disk.qcow2.sha256"
  retainGenerations: 2
  pollInterval: 5s
  importTimeout: 20m
placementPolicies:
  allowHostOverride: false
  allowClusterOverride: false
  allowVMGroupOverride: true
  allowedVMGroups:
    - "control-plane"
networkProfiles:
  talos-prod:
    networkName: "talos-prod"
    model: "virtio"
    contextMode: "auto"
storagePolicies:
  defaultDatastore: "ssd-primary"
observability:
  listenAddress: ":9977"
  metricsPath: "/metrics"
  healthPath: "/healthz"
  readyPath: "/readyz"
limits:
  maxVCPU: 16
  maxMemoryMiB: 65536
  maxRootDiskGiB: 200
  maxAdditionalDisks: 2
  maxAdditionalDiskGiB: 100
timeouts:
  instantiate: 2m
  vmReady: 10m
  terminate: 5m
flavors:
  small:
    cpu: "2"
    vcpu: 2
    memoryMiB: 4096
    rootDiskGiB: 40
  medium:
    cpu: "4"
    vcpu: 4
    memoryMiB: 8192
    rootDiskGiB: 80
```

## Notes

- Secrets do not belong in this file.
- If `allowedDatastores`, `allowedNetworks`, or `allowedTemplates` are empty, the provider does not restrict them.
- `imageNamePattern` should match the Talos image naming used in your OpenNebula image catalog.
- `imageManagement` turns missing-image resolution into a provider-managed import flow.
- `observability` exposes Prometheus metrics plus `/healthz` and `/readyz`.
